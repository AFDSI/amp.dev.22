
AMP has been exclusively client-side technology.
All resources needed to implement an HTML document are local to the document.
Example: all CSS is inline. CSS cannot be referenced as a remote, reusable library.
No JavaScript is allowed except for the AMP JS libraries.

Recently, AMP has begun to expose server-side processing.
One important feature that is in the roadmap (but not yet released) is content presentation based on permissions.
Currently, AMP downloads all content but displays only the first several 'articles' depending on whether the user has subscribed or not.
That feature depends on cookies.
A future release will control content access on the server.

We need to be proficient using AMP access control services for both the client and the server.
One important AMP page is here:
https://www.ampproject.org/docs/reference/components/amp-access

The first project is amp-form:
https://www.ampproject.org/docs/reference/components/amp-form
https://ampbyexample.com/components/amp-form/
Example:
	<form method="post" action-xhr="https://example.com/myform">
	...
	</form>
